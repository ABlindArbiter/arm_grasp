另外两个技术判断，先写在这里，后面会反复用到：

- **舵机角度 ≠ 关节角度。** 每个关节都要标定 `q = k·s + b`（s 是舵机指令角，q 是连杆转角）。这一步不做，你的 DH 表就是错的，后面所有误差都会算到手眼标定头上。

## 4. 先想清楚：5 自由度到底能做什么

这一节值得你花 20 分钟读三遍。它决定你后面所有任务的形状。

### 4.1 自由度账

要让末端到达一个**完整 6D 位姿**（位置 x,y,z + 姿态 roll,pitch,yaw），需要 6 个独立约束。你只有 5 个驱动关节，所以**至少有 1 维必须被固定**。

固定哪一维？固定「工具轴的方向」——让它始终**竖直向下**。此时末端位姿退化成 4 维：

```
(x, y, z, yaw)   ← 位置三点 + 绕竖直轴转一个角
```

5 个关节驱动 4 个任务维度，还剩 1 个冗余度用来「保证工具竖直」。这不是偷懒，是**数学必然**。

### 4.2 关节怎么分配（常见 5 轴构型）

| 关节 | 典型作用 | 在垂直下抓里干什么 |
|---|---|---|
| J1 | 底座回转（yaw） | 由目标 (x, y) 定：`J1 = atan2(y, x)` |
| J2 | 肩部俯仰 | 与 J3 一起解平面 2R（余弦定理） |
| J3 | 肘部俯仰 | 同上，有「肘上/肘下」两解 |
| J4 | 腕部俯仰 | 补偿到工具竖直：`J4 ≈ -(J2 + J3) + 常数`（取决于零位定义） |
| J5 | 腕部自转（roll） | 补足夹爪朝向：`J5 ≈ yaw − J1`（理想几何下） |

由此得到一个非常实用的结论：**给定 (x, y, z, yaw)，解析解唯一（除肘上/肘下两解）**，用限位和碰撞过滤即可。你根本不需要数值迭代，除非结构不标准。

### 4.3 工作空间（近似环带）

- 半径太小 → 撞基座；半径太大 → 臂全伸，进入奇异位形（J3 接近 0，雅可比退化，末端抖动）。
- 建议先划一个**保守任务区**：`r ∈ [15, 35] cm`、`z ∈ [2, 15] cm`（以桌面为 0）。具体数值 P1 用仿真扫出来，P2 用真机验证。
- **奇异点附近绝对不要放抓取目标**，舵机会因为微小指令跳变而剧烈动作。

### 4.4 已确认：6 舵机，J5 为自转（2026-11-10）

- 6 个舵机 = 5 关节 + 1 夹爪 → 上面 §4.2 的推导**成立**。
- J5 已确认是**绕工具轴自转（roll）** → `J5 = yaw − J1`，夹爪朝向可控，**能对齐物体长边**。

这个确认比看起来重要：它让 P4 可以多做一步「用物体主方向对齐夹爪开口」，抓方块和长条盒子的成功率会差很多。如果 J5 是俯仰，你只能抓对称物体。

> 剩下的不确定性只有「J4 与 J5 是否严格正交」——P1 用 FK 数值校验一遍即可，偏差 1–3° 属于正常，不用修，记录下来当误差源。

### P1 · 测绘 + 仿真 + 运动学（W3–W6，26 小时）

**目标**：不从头造轮子。用现成 URDF 改成你的臂、用现成库跑通 IK，你只负责「把你的臂描述对」和「把两种 IK 对比清楚」。

> 这一阶段的原则：**先让它动起来，再让它准起来。** 从零写 URDF、从零推数值迭代，都是重复劳动；你要练的是「判断哪个解对、误差从哪来」。

#### W3（6h）机械测绘与坐标系

- 卡尺/直尺量：底座到 J2 轴距离、J2–J3 连杆、J3–J4 连杆、J4 到夹爪中心。
- 定义基座坐标系：原点在底座回转中心与桌面交点，**z 向上，x 指向臂的正前方**。
- 手动把每个关节转到两个极限，用手机水平仪/量角器量角度，记进表。**这是软限位的物理依据。**
- J5 已确认是自转（roll），量一下它的零位：夹爪开口朝 +x 时算 0°。
- 画一张简图（手绘拍照即可），标出 5 个关节轴线和旋转方向。
- 产出：`docs/dh_table.md` 第一版 + 简图。

#### W4（6h）拿现成 URDF 改成你的臂（不从头写）

- 装两个工具：`pip install robot_descriptions yourdfpy`（前者提供几十个现成机器人模型，后者能读写 URDF）。
- 先加载一个现成的 5～6 自由度臂（`robot_descriptions` 里找 WidowX / Open Manipulator 这类；`pybullet_data` 里的模型也能直接用），确认能加载、能动、能调 IK。
- 打开它的 URDF，**只改三样**：连杆长度、关节限位、关节轴方向。改完存成 `sim/urdf/arm5.urdf`。
- 用 `yourdfpy` 打印关节树，确认「5 个可动关节 + 1 个夹爪」和你的实物一一对应。
- 统一约定写进 README：**弧度、米、右手系、旋转顺序 ZYX**。

> 为什么这样做：从零写 URDF 大概 4–6 小时，还要踩 mesh / origin / axis 的坑；改现成的 1–2 小时，且改的过程正好把「URDF 和 DH 的对应关系」搞明白——这才是你要学的东西。

#### W5（8h）先跑通库的 IK，再自己推解析解

**Step 1（2h）让库跑起来。** 用 `ikpy`（纯 Python，吃 URDF）或 PyBullet 的 `calculateInverseKinematics`，给定一个目标点，让仿真臂走过去，记录末端误差。**先有一个能用的东西，再谈原理。**

**Step 2（4h）自己推一遍解析解。** 按 §4.2：`J1 = atan2(y,x)` → 平面 2R 余弦定理解 J2/J3（两解）→ J4 补竖直 → J5 补 yaw。写成 `ik_analytic()`，输出候选解列表。

**Step 3（2h）对比，然后决定生产用哪个。** 同一批目标点，比较：位置误差、关节角差异、求解耗时、多解情况、奇异点表现。结论写进 `docs/dh_table.md`：
- **推荐：解析解为主（快、确定、可解释），库的 IK 做 fallback 和交叉校验。**
- 如果解析解在奇异点附近抖，就切库解——这个「切换策略」本身就是面试可讲的点。

#### W6（6h）轨迹 + 仿真闭环

- 关节空间梯形速度插值：加速、匀速、减速，限制最大关节速度/加速度（PyBullet 用 `setJointMotorControl2` 的位置控制即可，不用自己写 PID）。
- 仿真里：点一个目标 → IK → 轨迹 → 执行，末端画轨迹线。
- 加简单碰撞检查（至少保证末端不穿桌面）。
- 录一段 20 秒视频。

**验收**

- [ ] `sim/urdf/arm5.urdf` 能被 PyBullet 加载，关节数、限位与实测一致 → 截图 + 关节树输出
- [ ] 库 IK 与自写解析解在同一目标上位置误差 < 2 mm，差异有解释 → 对比表
- [ ] 100 个随机可达点：解析解成功率 > 90%，失败点分布有记录 → 统计输出
- [ ] 肘上/肘下两解都能正确给出，且能解释什么时候选哪个 → 代码 + 说明
- [ ] 轨迹执行时关节速度连续，无跳变 → 速度曲线图
- [ ] 工作空间散点图一张 → 图片
- [ ] 仿真视频 20 秒 → 链接

**常见坑**

- URDF 的 `origin` / `axis` 和 DH 参数不是一套语言。写完做一张「DH 第 i 行 ↔ URDF joint i」对照表，否则你会永远搞不清哪个对。
- `ikpy` 要指定 base link 和 end effector link，选错会差一整个关节。
- PyBullet 的 IK 返回的关节角顺序包含固定关节，索引别硬编码。
- 改 URDF 时不要动 mesh 和惯性参数，只动长度/限位/轴。
- 关节零位和舵机零位不是一回事。P1 先用「关节角」，P2 再建立 `servo = k·q + b` 映射。

### P2 · 真机链路（W7–W10，32 小时）

**目标**：让真机变成「仿真里那个臂」——同一组关节角，真机走到大致相同的位置，且有保护。

#### W7（8h）接线与首次上电

- 逐根确认舵机线序（信号/电源/地），不要凭颜色猜，用万用表通断档确认。
- **单舵机测试**：只接一个舵机，用 ZLink 官方上位机（若有）或最小串口指令，确认 ID、方向、行程。
- 逐个增加舵机，每加一个测一次。
- 电源检查：铭牌电压/电流 vs 5 个舵机堵转电流之和。**如果电源电流不足，会出现「一动就复位/丢指令」**——这是这套硬件最常见的坑。
- 加 1000–2200 µF 电解电容在 ZLink 电源输入端，抑制瞬态跌落。
- 急停方案：串联一个物理开关，或「手放在电源插头上」——**调试期间必须有一个 0.5 秒内能断电的手段**。

**上电前 10 项检查（打印出来贴桌上）**

1. 电源电压 = 舵机额定电压（用万用表实测，不是看标签）
2. 电源电流 ≥ 5 × 单舵机堵转电流 × 0.6
3. 所有地线共地（STM32、ZLink、电源负极）
4. 舵机线无短路（通断档测信号-电源）
5. 机械臂固定在桌面，底座不晃
6. 臂的运动范围内没有手、线、杂物
7. 软限位表已写入固件（还没写就先只测单关节小角度）
8. 急停手段就位
9. 首次测试速度 ≤ 30%
10. 有人在场，不无人值守运行

#### W8（8h）STM32 固件

- 串口协议：帧头 + 长度 + 命令字 + 数据 + CRC8/CRC16，波特率 ≥ 115200。
- 命令集最小化：`SET_JOINTS`、`READ_STATE`、`ESTOP`、`ENABLE`、`SET_SPEED`。
- 软限位校验：越界直接拒绝并回错误码，**不要 clamp 后静默执行**（会掩盖上游 bug）。
- 超时保护：500 ms 没收到指令 → 保持当前角度（或断电，二选一，写进文档）。
- 回读：角度、温度、电压（ZLink 支持就读，不支持就在文档里标注）。
- 堵转检测：位置误差持续 > 阈值 300 ms → 停止并上报。
- **不要在 STM32 里做运动学**，只做转发 + 保护。

#### W9（8h）Python 上位机

- `ArmController` 类：`connect / enable / set_joints / read_state / estop / close`。
- 后台线程持续读状态，主线程发指令，避免串口阻塞。
- 关节空间梯形插值放在上位机（STM32 只收目标角 + 速度）。
- CLI：`python -m arm.cli --joint 1 --angle 30`，支持 `home`、`read`、`estop`。
- 日志 CSV：`t, seq, cmd_q1..q5, act_q1..q5, cur, temp, volt, mode`。
- 用 matplotlib 画「指令 vs 实际」曲线。

#### W10（8h）仿真-真机对齐 + ROS2 旁路

- 同一组关节角，仿真末端位置 vs 真机末端位置（用卷尺/桌面标记/相机测），记 5 个点。
- 建立 `servo = k·q + b`：每个关节取两个已知角度点，解 k、b，写进 `config/servo_map.yaml`。
- 真机跑第一次 IK 点到点（先只走 x-y 平面，高度固定）。
- 记录偏差，**不要急着补偿**，先搞清楚偏差是系统性（可补偿）还是随机性（回差）。
- **ROS2 旁路（+2h，推荐）**：写一个只有 3 个文件的桥——订阅 `ArmController` 的内部状态，发 `sensor_msgs/JointState`，并用 `tf2` 发 `base_link → link1..5 → tool`。
  - `ros2 run tf2_tools view_frames` 能看到坐标树；
  - rviz2 里加载你的 URDF，真机动一下，rviz2 里的模型同步动——**这是你调试「到底哪个关节反了」最快的方法**；
  - 用 `ros2 bag record -a` 录 30 秒，以后可以离线回放复盘。

**验收**

- [ ] 发角度指令，臂平稳到位，回读误差 < 2° → 日志
- [ ] 越界指令被拒绝并返回错误码 → 截图
- [ ] 急停生效（0.5 秒内停）→ 视频
- [ ] 拔掉串口，500 ms 后进入保护 → 日志
- [ ] 一份 CSV 能画出指令/实际曲线 → 图
- [ ] 仿真 vs 真机 5 点偏差 < 3 cm → 表格
- [ ] 连续运行 10 分钟不掉线、不复位 → 日志

**常见坑**

- 共地不良 → 舵机一动 STM32 就复位。表现是「随机重启」，很容易误判成固件 bug。
- 电源电流不足 → 多关节同时启动时电压跌落，同样表现为复位/丢包。**先测电压跌落，再怀疑代码。**
- 舵机 ID 冲突/方向反了 → 用单关节测试逐个确认，别一次全接。
- 串口粘包/半包 → 协议必须有帧头和长度，且上位机要处理「一次读到半帧」。

**交接给 P3 的东西**：`ArmController` API、servo 映射表、限位表、CSV 日志样例、真机重复定位精度（粗测）。

### P3 · ZED 深度 + 手眼标定（W11–W15，38 小时）

**目标**：打通「相机看到的三维点」→「机械臂基座坐标」。这是整个项目最核心、也最容易卡住的一步。

#### W11（8h）ZED SDK 基础

- 打开相机：分辨率、帧率、深度模式（`NEURAL` / `ULTRA` / `PERFORMANCE` 按场景选）。
- 取：彩色图、深度图、点云、置信度图。
- **验证坐标系**：把一个物体放在相机正前方偏右，看它的 x 是正还是负；放在下方，看 y 是正还是负。写进 `docs/`。
- 保存一帧到磁盘，之后所有调试用这一帧，保证可复现。
- OpenCV 显示彩色 + 深度伪彩；Open3D 显示点云。
- **ROS2 旁路（+1h）**：把点云发成 `sensor_msgs/PointCloud2`，配一个 `base_link → camera_link` 的静态 TF（先用卷尺估的粗略值），在 rviz2 里叠加看。手眼标定完成后换成标定矩阵，**能一眼看出「点云和机械臂是不是在同一个世界里」**。

#### W12（7h）深度质量与预处理

- 深度误差测试：白墙/纸板分别在 0.3 / 0.5 / 0.8 / 1.2 m，各测 100 个像素，算均值、标准差。**这张表后面用来判断「抓不准是不是深度的锅」。**
- 置信度过滤、距离裁剪（`0.2–1.0 m`）、统计离群点去除、体素下采样。
- 结论写进文档：在你的工作距离上，ZED 的深度噪声大概是多少毫米。

#### W13（8h）标定原理 + 仿真标定

- 理解 `AX = XB`：A 是末端位姿变化，B 是相机看到的标定板位姿变化，X 是手眼矩阵。
- 为什么至少要 3 组**非共面**姿态；为什么旋转误差会放大平移误差。
- **在 PyBullet 里做一次虚拟标定**：已知相机外参真值，生成 20 组「末端位姿 + 标定板位姿」，喂给你的标定代码，看解出来的 X 和真值差多少。
- 这一步的意义：**证明你的代码是对的**。真机标定失败时，你才能确定问题在数据。

#### W14（8h）真机手眼标定

- 打印棋盘格（A4，9×7 内角点，方格 20 mm），**贴在硬纸板/亚克力上，必须平整**。翘曲 1 mm 就能让你的标定差 5 mm。
- 相机固定在三脚架上（eye-to-base），**标定期间绝对不能碰**。
- 采 15–20 组：每组记录「机械臂末端位姿（由 FK 算）+ 相机检测到的标定板位姿（`solvePnP`）」。
- 姿态要多样：至少 3 个不同朝向 + 2 个不同距离；每组都**从同一方向接近**目标点，减少回差。
- 用 `cv2.calibrateHandEye` 跑 TSAI / PARK / HORAUD / ANDREFF 四种，对比残差，选最小的。写进文档，说明为什么选它。

#### W15（7h）验证 + 缓冲

- 触碰验证：在桌面放 5 个标志点，相机测 3D → 手眼变换 → 基座坐标 → IK → 臂去触碰，量误差。
- 如果误差 > 25 mm，按顺序排查：标定板平整度 → 采点姿态多样性 → 臂回差（同一点正反向各来一次）→ 相机是否被碰过 → 深度噪声。
- 画坐标链路图：`像素 → 相机 → 基座 → 末端`，每段标注矩阵名。

**验收**

- [ ] ZED 稳定出图，一帧数据可复现加载 → 文件
- [ ] 深度误差表（4 个距离 × 均值/标准差）→ 表格
- [ ] 仿真标定：解出的 X 与真值平移误差 < 2 mm → 数值
- [ ] 真机标定平移残差 < 10 mm、旋转 < 2°（目标值，达不到就记录实际值）→ 数值
- [ ] 触碰 5 点：平均 < 15 mm，最大 < 25 mm → 表格
- [ ] 坐标链路图 → 图片

**常见坑**

- ZED 的 y 轴向下。用错符号，点云会上下颠倒，且看起来「像是标定错了」。
- 标定板不平、反光、打印比例不对（打印机缩放）→ 全部废掉。**打印后用卡尺量方格实际尺寸。**
- 采点时臂的关节角读数不准（编码器分辨率/回差）→ 标定残差大。这是舵机臂的硬伤，只能靠「同向接近 + 多组平均」缓解。
- 相机支架不稳 → 你以为标定好了，第二天全偏。**标定完在支架上贴个标记，每次用前检查。**

**交接给 P4 的东西**：手眼矩阵（4×4）、坐标链路图、深度误差表、触碰误差表、相机安装位置照片。

### P4 · 静态抓取闭环（W16–W20，38 小时）

**目标**：从「能走点」到「能自己抓」。先用最笨的方法跑通，再换聪明的。

#### W16（8h）传统 CV 基线

- HSV 阈值分割 → 轮廓 → 最小外接矩形 → 中心像素。
- 在中心附近取 5×5 深度窗口中值 → 反投影 → 相机系 3D 点 → 手眼 → 基座系。
- 固定抓取时序（**这是工业界标准流程，不要一上来搞 RRT**）：

```
HOME → 安全高度(z=15cm) → 目标正上方 → 匀速下降 → 闭合夹爪
→ 抬升到安全高度 → 移动到放置点 → 下降 → 松开 → 回 HOME
```

- 每个阶段之间用关节空间梯形插值，禁止瞬跳。

#### W17（8h）联调 + 误差补偿

- 跑 10 次，记录每次失败类型（抓空 / 抓偏 / 撞桌 / 滑落）。
- 若误差是**系统性**的（每次都偏同一方向）→ 在基座系加固定偏移 `offset`，写进 yaml。
- 若误差是**随机**的（有时左有时右）→ 是回差/重复定位问题，靠「同向接近 + 降低速度」缓解，不要用 offset 硬补。
- 加安全高度、下降速度限制、夹爪闭合后等待 200 ms。

#### W18（8h）YOLO 替换

- 先用 `ultralytics` 的现成 COCO 模型（不用训练）检测「bottle / cup / sports ball」，验证整条链路能接上。
- bbox 中心 → 深度采样 → 3D 点。注意 bbox 中心可能不在物体上（背景），要加深度有效性检查。
- 对比传统 CV：成功率、速度、对光照的敏感度。
- 可选：自己标 50 张图微调（`yolov8n`），作为加分项，不是必做。

#### W19（7h）分割 + 多点采样

- `yolo11n-seg` 出 mask → mask 内所有有效深度点 → 取中位数/均值 → 更稳的 3D 中心。
- 处理遮挡：mask 面积太小或深度点太少 → 判定「不可抓」，跳过。
- 物体主方向（PCA）→ 夹爪开口对齐长边（如果 J5 可控）。

#### W20（7h）稳定性 + 节奏

- 连续 20 次抓取，统计成功率；换 3 种物体（方块、圆柱、小盒）。
- 单次 cycle 时间统计。
- 录 demo 视频（俯拍 + 侧拍各一段）。
- 更新 README。

**验收**

- [ ] 方块连续 20 次，成功率 ≥ 70% → 表格
- [ ] 3 种物体各 10 次，成功率 ≥ 50% → 表格
- [ ] 全流程无人工干预，单次 < 30 s → 视频
- [ ] 失败分析表（失败类型 / 次数 / 根因 / 修复）→ 文档
- [ ] 能画出「检测 → 3D 点 → 基座坐标 → 关节角」的数据流图 → 图片

**常见坑**

- 深度采样点在物体边缘 → 深度是背景的，3D 点飞到墙里。**必须取窗口内值 + 剔除离群。**
- 抓取姿态固定垂直向下，但物体在臂的工作空间边缘 → IK 无解或接近奇异。**先限制物体摆放区域。**
- 夹爪闭合后立刻抬升 → 物体没夹稳，滑落。**加 200 ms 保持。**

### P5 · 工程化与误差建模（W21–W24，28 小时）

**目标**：把「能跑」变成「能解释、能复现、能改进」。这一段是简历上「工程能力」的来源。

#### W21（7h）误差测量

- 用 `ros2 bag` 把一次完整抓取录下来，作为「可复现证据」放进仓库。

- 如果 W23 结束时 ROS2 版还没稳，**保留纯 Python 版为默认入口**，ROS2 版作为 `ros2/` 子目录的加分项——不要让求职项目卡在一个没必要的重构上。

## 6. 数学最小包（6 小时，只补够用的）

你的线代没问题，缺的是「机器人学那套用法」。**不要去买《机器人学导论》从头读**，先补这 6 个式子，够你用到 P5。

### 6.1 六个必须能徒手写出来的式子

1. **齐次变换**
   ```
   T = [ R  t ]      T⁻¹ = [ Rᵀ  −Rᵀt ]
       [ 0  1 ]            [ 0     1  ]
   ```
2. **复合**：`T_0_3 = T_0_1 · T_1_2 · T_2_3`（左乘 = 在基座系里变换，右乘 = 在自身系里变换）
3. **绕 z 轴旋转**
   ```
   Rz(θ) = [ cosθ −sinθ 0 ]
           [ sinθ  cosθ 0 ]
           [  0     0   1 ]
   ```
4. **点变换**：`p_b = R · p_c + t`
5. **平面 2R 逆解（余弦定理）**
   ```
   cos(q3) = (r² − L1² − L2²) / (2·L1·L2)
   ```
6. **AX = XB 的含义**：同一块标定板，在「末端坐标系」和「相机坐标系」里看到的两组位姿，差一个固定的 X。

### 6.2 四小时怎么花

| 时长 | 内容 | 练习 |
|---|---|---|
| 1h | 2D 旋转/平移 → 3D 齐次；复合顺序 | 手算一个 3 段连杆的 T |
| 1h | 逆变换、点变换 | 写 `inv(T)` 并与 `np.linalg.inv` 对比 |
| 1h | 欧拉角/旋转向量/四元数互转（用 `scipy.spatial.transform.Rotation`，不要求手推） | 转 10 组随机旋转，往返误差 < 1e-6 |
| 1h | 用 numpy 写 `fk` 的骨架 + pytest | 3 个测试：单位变换、单关节、复合 |

### 6.3 自测（答不出来就回去补）

1. `T_0_3 = T_0_1·T_1_2·T_2_3` 和 `T_0_3 = T_0_2·T_2_3` 哪个对？为什么？
2. 一个点 `p = (1,0,0)`，先绕 z 转 90°，再沿 x 平移 1，结果是多少？如果先平移再旋转呢？
3. `R` 是旋转矩阵，`RᵀR = ?`，`det(R) = ?`
4. 为什么 2R 平面臂的逆解通常有两个？
5. 手眼标定里，如果相机和臂的相对位置变了，`AX = XB` 里的哪个量会失效？

> 答案在 P0 台账里自己写一遍，别只在大脑里过。

## 7. 调试能力专项（你最大的短板）

你说「主要靠 AI 改，自己排查弱」。这不是能力问题，是**方法问题**，可以练。

### 7.1 五个必须养成的动作

1. **先写三行再问 AI**：
   ```
   预期：我期望发生 X
   现象：实际发生 Y
   差异：我怀疑在 A 和 B 之间
   ```
   没有这三行，不许打开 AI。三个月后你会发现，80% 的问题在写这三行时就解决了。
2. **分层隔离**：`PC → 串口 → STM32 → ZLink → 舵机`，每一层都要有独立可测点。出问题先把范围砍一半，不要从整条链路猜。
3. **二分法**：改一个变量，测一次。同时改三个参数再看结果 = 白测。
4. **日志带时间戳和序号**：没有日志的调试 = 玄学。CSV 里要有 `t, seq, cmd, actual, err, mode`。
5. **保留能跑的最小基线**：每次加新模块前 `git tag baseline-vN`。新模块崩了，`git checkout` 回去，而不是从头修。

### 7.2 每周 30 分钟「断网排查」训练

每周挑一个你已经修好的 bug，**关掉 AI，只看代码和日志，重新走一遍排查过程**，写下「如果当时我有这个方法，能省多久」。年底这 26 次训练，比多写 2000 行代码值钱。

### 7.3 面试怎么讲调试（模板）

> 「现象是 X。我先看了日志，发现 Y 在 Z 时刻异常，于是把范围缩到 A 层。用万用表/回环测试排除了 B，最后定位到 C。根因是 D，修复方式是 E，之后我加了 F 防止复发。」

这段话的结构（现象 → 证据 → 缩小范围 → 根因 → 修复 → 防复发）比答案本身重要。

## 8. AI 使用边界：红黄绿

你现在的模式是「AI 写，我改」。这在学习期很危险，因为**面试不会给你 AI**。定三条线：

| 灯 | 可以做 | 例子 |
|---|---|---|
| 🟢 绿 | 查 API、生成样板代码、解释报错、写测试、重构、画图 | 「pyzed 怎么取点云」「这段报错什么意思」 |
| 🟡 黄 | 核心算法**必须先自己写伪代码/公式**，AI 只做 review | IK 推导、标定流程、坐标变换 |
| 🔴 红 | 不许让 AI 直接产出「能跑的完整方案」然后你不理解就跑 | 「帮我写一个完整的抓取程序」 |

**自检方法**：每段 AI 生成的代码，你能不能在不看代码的情况下，说出它的**输入、输出、中间数据流**？说不出来 = 红灯，删了重写。

**每周一次「费曼测试」**：挑一个本周学的概念，用 3 分钟讲给一个不懂的人听（可以录下来自己听）。讲不顺 = 没懂。

## 13. 选修支线库（主线不掉队才能开，一次只开一个）

| 支线 | 工时 | 前置 | 价值 | 建议 |
|---|---|---|---|---|
| 抓取生成网络（GG-CNN / GraspNet） | 20–30h | P4 完成 | 简历亮点，但真机 5 自由度用不上 6D 抓取 | 只在仿真里做 |
| 强化学习抓取（PyBullet + SAC） | 30h | P4 + 仿真 | 面试话题性强，但难出真机结果 | 仿真里做，当作第二项目 |
| SLAM / VIO（ZED positional tracking、ORB-SLAM3） | 30h | P3 | 拓宽岗位面，但与抓取主线弱相关 | 单独小项目，不要混进主线 |
| Isaac Sim | 20h | P1 | 仿真更真实，但学习曲线陡 | 可选，PyBullet 够用 |
| MoveIt2 | 15h | P2 | 5 自由度配置成本高、收益低 | **明确不做**，面试时讲「为什么不做」比硬做加分 |

**规则**：支线必须**独立仓库或独立分支**，不许污染主线。主线连续两周没进展 → 关掉支线。
