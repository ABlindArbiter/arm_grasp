# 使用手册：从今天开始，每次怎么开新对话

> 一句话：**所有记忆都在文件里，不在对话里。**
> 阶段结束 = 更新台账 → 开新对话 → 粘贴开场白 → 附三个文件。

---

## 0. 先搞清两件事

### 0.1 这个对话 vs 新对话，分工不同

| 对话 | 用来干什么 | 什么时候用 |
|---|---|---|
| **本对话（计划对话）** | 改计划、问概念、解释文档、调整节奏 | 计划本身要变时 |
| **阶段对话（每个阶段新开）** | 执行任务、验收、进入下一阶段 | 每阶段开头 |

你不需要回到这个对话「汇报」——它不会记住你。真正的汇报对象是 `01_进度台账.md`。

### 0.2 为什么必须开新对话

- 一个阶段 4–5 周，对话会变得很长，AI 的注意力会被稀释；
- 新对话 + 三个文件 = 干净、聚焦、可复现；
- 文件是唯一不会丢的东西。对话丢了，台账还在。

## 1. 今天先做这 4 步（30 分钟）

```bash
# 1) 建目录、拿脚本
mkdir -p ~/arm-grasp && cd ~/arm-grasp
cp <计划文件夹>/tools/git_helper.sh .
chmod +x git_helper.sh

# 2) 初始化（会建目录骨架 + .gitignore + 首次提交）
./git_helper.sh init

# 3) 把计划文件也放进仓库（重要：计划跟着代码走，永不丢）
mkdir -p docs/plan
cp <计划文件夹>/0*.md docs/plan/
./git_helper.sh save "docs: 加入学习计划与台账"

# 4) 配 SSH，然后连远端（GitHub 先建空仓库）
ssh-keygen -t ed25519 -C "你的邮箱"
cat ~/.ssh/id_ed25519.pub      # 粘到 GitHub → Settings → SSH keys
ssh -T git@github.com          # 看到 Hi 用户名 就成功
./git_helper.sh remote git@github.com:你的用户名/arm-grasp.git
```

**顺便把采购下单了**（到货要一周，别等 P2 才买）：

- 电解电容 1000–2200 µF × 2（5–10 元）
- A4 棋盘格打印 + 硬纸板背板（10–20 元）
- 备用舵机 × 1（同型号，60–100 元）
- 杜邦线 / 热缩管 / 保险丝（30 元）

## 2. 文档要读几个？读哪几段？

**不要通读。** 00 有 800 多行，第一天读完只会忘。按下面读，W1 总共约 40 分钟。

| 文档 | 读多少 | 什么时候 | 怎么读 |
|---|---|---|---|
| `00_总纲` | §0 全部 + §1.1 + §5.1 + **P0 那一节** + §6 | 今天，25 min | 其余章节当字典，用到再翻 |
| `00_总纲` | §4（5 自由度边界）+ P1 节 | P1 开始前，20 min | 只读这两块 |
| `00_总纲` | 对应阶段的「任务 + 验收 + 常见坑」 | 每阶段开始前 | 只读本阶段，别提前读下一阶段 |
| `01_台账` | 不读，**只填** | 每周日 + 阶段末 | 填数字，不写作文 |
| `02_交接模板` | 只读 §一 开场模板 + §四 | 阶段结束时，10 min | 复制粘贴，改数字 |
| `03_硬件清单` | 不读，**填** | 本周 | 填表 + 拍照 |
| `04_Git` | §0 术语表 + §5 五命令 | 今天，10 min | 其余（报错对照）遇到再看 |
| `05_资料` | **只看当前阶段那张表** | 每阶段开始，5 min | 挑 1 主 1 备，别往下翻 |

> 判断标准：**读完能立刻做一件事**，才继续读。读完不能动手的段落，跳过。

## 3. 第一周逐日（按 7.5 小时排，可前后挪）

| 天 | 时长 | 做什么 | 产出 |
|---|---|---|---|
| D1 | 30 min | §1 的 4 步：建仓库、配 SSH、计划入仓、下单 | 仓库链接 |
| D2 | 1.5h | 填 `03` 的舵机表 + ZLink + 电源（拍照），不知道的标红 | 盘点表 v1 |
| D3 | 1.5h | 装 ZED SDK（先 `nvidia-smi` 通），跑 ZED Explorer / Depth Viewer | 彩色图 + 深度图 |
| D4 | 1.5h | 装 PyBullet + `robot_descriptions`，加载一个现成臂，能动 | 10 秒录屏 |
| D5 | 1h | 写 `transforms.py`：齐次变换、求逆、复合 | 能跑的代码 |
| D6 | 2h | 写 3 个 pytest + 修 bug | `pytest -q` 全绿 |
| D7 | 0.5h | 填台账 W1 + `sync` + `tag w1` | 台账 W1 行 |

> **本周不接线通电。** P0 只做盘点、环境、数学。

## 4. 每天 / 每周的固定动作

**每次坐下来（2 分钟）**：看一眼 `docs/debug_log.md` 最后三行（现在能跑 / 下一步 / 卡在）。

**每次结束（1 分钟）**：
```bash
./git_helper.sh save "feat(xxx): 一句话说明"
```
并在 `docs/debug_log.md` 末尾更新那三行。

**每周日（30 分钟）**：填台账 W__ 行 → `sync` → 有验收就 `tag wN`。

---

## 5. 阶段结束：5 步，15 分钟

1. **对照验收表**，逐条打分，每条写证据（数值/文件/视频/commit）。
2. **填 `01_台账` 的阶段卡片**：通过几项、未过哪项差多少、卡点、自评。
3. **更新 `02` 配置区**：手眼矩阵、DH 表、误差数据（这些是下阶段的前提）。
4. **提交并打标签**：
   ```bash
   ./git_helper.sh save "docs: P2 阶段验收"
   ./git_helper.sh tag p2-pass
   ./git_helper.sh sync
   ```
5. **开新对话**，用下面的开场白。

## 6. 新对话开场白（复制这段，填 5 个空）

### 6.0 开局（P0 第一天用这个，不是交接模板）

```
【开始 P0】机械臂视觉抓取学习计划
我是大三学生，全程 Ubuntu 22.04 + ROS2 Humble + 40 系显卡。
附件：00_总纲与学习计划.md、01_进度台账.md、03_硬件盘点清单.md

硬件现状：5 自由度舵机臂（6 舵机，J5 自转），原装主控已拆但未接线；
ZED-M 已到手，SDK 未装。目标 P0（W1–W2，14h），本周只有 7.5 小时。

请：
1) 先问我 3 个问题，确认我对 P0 目标的理解没跑偏（不是考试）；
2) 给我 W1 逐日任务（每天 ≤1.5h），每条带「验收证据」格式；
3) 告诉我第一天最容易做错的一件事。
不要给两周任务，不要一次给完整代码。中文讲解。
```

> 注意：P0 之前没有「上一阶段」，所以不要用下面的交接模板。

### 6.1 阶段交接模板

```
【阶段交接】机械臂视觉抓取学习计划

我是大三学生，全程 Ubuntu 22.04 + ROS2 Humble。
附件：00_总纲与学习计划.md、01_进度台账.md

上一阶段：P__（____），计划 W__–W__，实际投入 __ 小时。
验收：__/__ 条通过。未过的是：____（差多少）。
关键数据：____（见下方「必须报的数」）。
仓库：____ 分支 main，最新 tag：____。
卡点：____（现象 / 已排除 / 我的假设）。
自评：掌握最好的是 ____，最心虚的是 ____。

请按 02_阶段交接模板 的评估协议执行：
1) 随机抽 5 题考我，不要我说「会了」就算；
2) 指出台账里证据不足或数据可疑的地方；
3) 给结论：通过 / 补课（列清单+工时）/ 降级；
4) 通过后，只给下一阶段第一周的任务，不要一次给四周。
中文讲解，英文术语保留原文。
```

### 每次必须报的 3 个数（别的可以少说）

| 过渡 | 报这三个 |
|---|---|
| 开局 P0 | 舵机数（6）、J5 是否自转、ZED 是否已装 |
| P0 → P1 | J5 零位角、连杆长度、ZED 是否出图 |
| P1 → P2 | IK 成功率、库解与解析解误差、URDF 是否加载成功 |
| P2 → P3 | 回读误差、三项安全测试是否通过、仿真/真机偏差 |
| P3 → P4 | 手眼平移残差、触碰平均误差、深度误差（工作距离处） |
| P4 → P5 | 20 次成功率、主要失败类型、单次 cycle 时间 |
| P5 → P6 | 误差来源前三项、pytest 是否全绿、ROS2 bag 能否回放 |

### 一个填好的例子（P0 → P1）

> 上一阶段：P0 地基，计划 W1–W2，实际 9 小时。
> 验收：4/6 条通过。未过：ZED 出图（SDK 装完但 pyzed 报错）、数学自测 4/5。
> 关键数据：J5 零位 0°（夹爪朝 +x）、连杆 12/15/10 cm、ZED 未出图。
> 仓库：github.com/xxx/arm-grasp，tag p0-partial。
> 卡点：pyzed import 报 `libturbojpeg` 找不到；已排除驱动问题。

## 7. 卡在阶段中间怎么办（不换阶段）

```
【卡点求助】P__ 阶段，已卡 __ 小时
期望：____
实际：____
已排除：____（做了什么测试，结果如何）
假设：____
相关文件/日志：____（路径 + 关键 20 行）
请：先别给答案，先问我 3 个能缩小范围的问题。
```

> 关键：**先给「期望/实际/已排除」**，AI 才能帮你缩范围；只说「不 work」，只能得到一堆猜测。

---

## 8. 三个不要

1. **不要先接线通电**。没有限位表和保护逻辑，一次扫到自身就可能烧舵机。
2. **不要囤资料**。每阶段 2 个，看完再开。看视频的爽感会骗你。
3. **不要攒着不提交**。「做完再传一次」= 没有安全网，也没有作品集。

---

## 9. 如果中途计划要改

- 小改（延一周、换资料）：直接改台账「变更记录」，不用问。
- 大改（砍阶段、换方案、改目标）：回**本对话**问，说明「原来怎样 / 为什么改 / 想改成什么」，我帮你评估连锁影响。
